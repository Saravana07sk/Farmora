Full-Stack Agricultural Marketplace

AgriLink

Connecting Farms Directly to Markets

A digital platform that connects verified farmers with buyers, improves price transparency, and manages the complete marketplace workflow.

Project Presentation

1. Problem Statement

Challenges for Farmers

  • Dependence on intermediaries
  • Unstable and unclear pricing
  • Difficulty reaching direct buyers
  • Limited digital inventory tools

Challenges for Buyers

  • Limited information about product origin
  • Inconsistent quality and availability
  • Hidden or unclear charges
  • Difficulty finding trusted farmers

AgriLink addresses these problems with one transparent, role-based online marketplace.

AgriLink01

2. Proposed Solution

  • Farmers create and manage produce listings.
  • Buyers browse products and place orders directly.
  • Farmer verification increases trust on the platform.
  • Inventory, order status, pricing, and analytics are managed digitally.
  • Administrators moderate users and marketplace content.

Project Objectives

Connect farmers directly with customers.
Improve farmer earnings and market access.
Provide transparent pricing and secure ordering.
Support data-driven marketplace decisions.

4. Main Features

Marketplace

Search, category, price, location, quality-grade, farming-method, and verified-farmer filters.

Produce Management

Product name, category, price, unit, quantity, minimum order quantity, quality grade, farming method, location, and images.

Order Fulfillment

PLACED -> CONFIRMED -> PROCESSING -> READY_FOR_DELIVERY
       -> OUT_FOR_DELIVERY -> DELIVERED

Analytics

Farmers can view sales performance, while administrators can view marketplace GMV, platform commissions, active listings, and category statistics.

5. Transparent Pricing

The buyer sees the complete price before placing an order.

Total Payable = Produce Subtotal + Platform Fee + Delivery Fee

Example

ComponentAmount
Produce subtotalRs. 1,000
Platform fee: 3%Rs. 30
Delivery feeRs. 70
Total payableRs. 1,100

This pricing model reduces confusion and builds trust between buyers and the platform.

7. System Architecture

Buyer / Farmer / Administrator
              |
       React Frontend
              |
       Express REST API
              |
 Authentication and Authorization
              |
 Controllers and Business Logic
              |
       Mongoose Models
              |
       MongoDB Database

The frontend sends requests to the backend. The backend validates permissions, applies marketplace rules, and reads or writes data in MongoDB.

Running Services

Frontend: http://localhost:5173
Backend: http://localhost:5000
Database: mongodb://127.0.0.1:27017/agrilink

9. Database Design

Collections

  • Users
  • Products
  • Orders
  • Cart
  • Reviews
  • Notifications
  • Audit logs

Relationships

  • A farmer owns product listings.
  • A buyer creates orders.
  • Orders contain product references.
  • Buyers submit reviews.
  • Important actions create audit records.

Live Connection

The application connects through the server environment variable:

MONGODB_URI=mongodb://127.0.0.1:27017/agrilink

The products API has been verified and returns MongoDB-backed product data.

AgriLink09

10. Security

  • JWT-based authentication
  • Password hashing with bcryptjs
  • Role-based authorization
  • Protected farmer, buyer, and admin routes
  • Helmet security headers
  • API rate limiting
  • Input and request validation
  • Stock and minimum-order validation
  • Audit logging for important actions

Why It Matters

These controls protect user accounts, prevent unauthorized actions, and help maintain reliable marketplace operations.
